# Student Academic Performance Prediction & Social Media Impact Analysis System

A working prototype that predicts a student's CGPA from a social-media/
study-habits questionnaire using Linear Regression, then gives rule-based,
personalized improvement suggestions. Built per the project handoff
document, Phase 1 (CGPA regression only — `CGPA_Binary` is intentionally
excluded until Phase 2).

## Project structure

```
student_project/
├── app.py                  # Streamlit application (Home / Predict / My Analysis / About Model)
├── data/
│   └── dataset.xlsx         # The cleaned Google Form responses (208 rows x 20 cols)
├── src/
│   ├── preprocessing.py     # Column mapping, cleaning rules, multi-label encoder
│   ├── train_model.py       # Trains + evaluates the pipeline, saves artifacts
│   └── recommendations.py   # Rule-based study-pattern analysis
├── model/                   # Generated by train_model.py (not checked in by hand)

│   ├── model_metrics.json
│   └── feature_schema.json
├── requirements.txt

```

## How to run

```bash
pip install -r requirements.txt

# Train the model (also runs automatically on first `streamlit run` if
# the model/ folder is empty)
python src/train_model.py

# Launch the app
streamlit run app.py
```

## What was excluded from the model, and why

| Excluded field | Reason |
|---|---|
| Timestamp, Email, Roll No, Name | Personal identifiers — not predictive, and shouldn't be exposed |
| CGPA | This is the target itself |
| CGPA_Binary | Reserved for a future Phase 2 classification model |
| "Compared to previous semester..." | An academic-outcome question — using it to predict CGPA would leak target information |
| "1–10, how much social media affected your grades" | A self-reported judgement about grade impact. It overlaps conceptually with the target rather than being an independent behavioural signal, so it carries the same kind of leakage risk as the previous-semester field. Excluded per the handoff document's instruction to make this decision explicitly. |

## Data cleaning applied

- **Age**: values outside 15–30 treated as missing (raw data ranged 10–44), then median-imputed.
- **Daily social-media time**: must be `0 < hours <= 24`; the ~40 hours/day outlier is treated as missing.
- **Study-time frequency (1–10 scale)**: must be `0 <= value <= 10`; the `-1` outlier is treated as missing.
- **Platform name typos** (e.g. "Linkdin" vs "LinkedIn") folded together before encoding.
- Missing numeric values → median imputation. Missing/unknown categorical values → most-frequent imputation, with `handle_unknown="ignore"` so a brand-new category typed by a future user never crashes the app.

## Honest model performance (from the last training run)

See **About Model** in the app, or `model/model_metrics.json`, for the exact numbers produced by
this dataset. As of this build:

- Test R² and 5-fold CV R² are **negative**, meaning the model currently performs worse than
  simply predicting the average CGPA for everyone.
- This is reported as-is. It is not a bug in the pipeline — it reflects that this is a small
  (208-row), self-reported, single-institution dataset, and CGPA is influenced by many factors
  a habits questionnaire alone does not capture.
- Do **not** replace these numbers with the discarded earlier run's metrics (MAE 1.30 / RMSE 1.60
  / R² -0.61) — those came from a version that incorrectly leaked `Name` and the
  previous-semester field into the features, and must not be cited anywhere.

### Talking points for your viva

- You can honestly say: *"With this dataset size and these features, a linear model does not yet
  explain CGPA variance better than the mean — this is a common, expected result for small
  self-reported survey datasets, and the prototype reports it transparently rather than hiding it."*
- You can also describe what would likely help in Phase 2: more responses, potentially non-linear
  models, and using `CGPA_Binary` for a classification framing instead of exact-value regression.
